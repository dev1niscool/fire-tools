# Security review of Hayden Plumley’s Fire Tools

On November 27, 2026 we inspected the public `mrhaydendp/Fire-Tools` source and both downloads from its latest published release. The most consequential finding was in **Disable**. On both Windows and POSIX it clears an app’s data after disabling the package. **Undo** can re-enable the app, but its local data is gone. This applies even to an individually selected package. [Windows implementation](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/PowerShell/debloat.ps1#L8-L16) · [POSIX implementation](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/Posix/debloat.sh#L9-L19)

## What the code does

| Action | Observed behavior and consequence |
| --- | --- |
| Debloat and OTA | The bulk list has 114 entries on `main` and 111 in the release. Both include app verification, parental controls and Device Setup. Bulk debloat also writes location, advertising, telemetry, lock-screen and animation settings. Undo uses fixed settings and does not record the initial state. The separate OTA button sends three update-related packages through the same disable-and-clear path. [Package list](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Debloat.txt) · [Bulk settings](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/Posix/debloat.sh#L21-L57) |
| APKs and launchers | Single APK and split APKM installs request all grantable runtime permissions with `-g`. Scripts unpack split archives into a shared `Split` folder and suppress install diagnostics. Cleanup can mask a failed install. The Google button attempts every matching file in `Gapps`, including two framework versions in the release, then tries the Store again. Launcher setup may install the bundled LauncherHijack fallback. The scripts perform no signer or expected-hash check. [Installer](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/Posix/appinstaller.sh) · [Google button](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/main.py#L120-L129) |
| Host installation and updates | The user-triggered updater overwrites active scripts from the mutable `main` branch. In Python mode it downloads a requirements file and runs pip. It checks neither HTTP success nor a digest before writing files. Setup scripts fetch the latest release and can install host dependencies. The POSIX Homebrew fallback executes a downloaded script. A later update therefore has its own trust decision. [Updater](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/main.py#L61-L92) · [POSIX setup](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/Posix/install.sh) · [Windows setup](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/PowerShell/install.ps1) |
| Tablet identification and DNS | The identifier downloads Amazon’s public device table on a cache miss and looks up the reported model locally. The DNS control writes the selected hostname into Android’s global settings. The ADB commands rely on the default device target, which can be ambiguous with multiple attached devices. [Identifier](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Scripts/Posix/identify.sh) · [DNS control](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/main.py#L104-L118) |

Our toolkit uses an offline Amazon model table, six named DNS choices with undo and a folder installer that previews standalone APKs. The POSIX launcher supports tablet workflows on Linux. On macOS it supports the offline demo and file checks. Native macOS 15 testing found the directory-pinning support required for tablet changes was unavailable. Of the 114 IDs in Hayden’s list, 19 appear in our 22-package Standard preset and 26 appear in our 35-package Complete preset. Our guided package actions protect services such as app verification and the VoiceView screen reader. Clearing app data requires its own action. Our release ships independent source and includes none of Hayden’s code or bundled APKs. ## Android package provenance

Android SDK Build Tools 36 `apksigner` verified all 65 APKs inside the seven packages. Google Play services and both Services Framework versions used Google's legacy certificate. The Store used a rotated Google certificate, and its base APK contained the signing lineage back to that legacy key. The two Framework APKs, the Store APKM and Nova Launcher 7.0.58 matched APKMirror’s listing hashes. Lawnchair and LauncherHijack matched the files downloaded from their project releases byte for byte. [Google app listings](https://github.com/mrhaydendp/Fire-Tools/blob/3a03e71b792878ec24d7118a6aeac0c7237a1431/Fire-Tools/Gapps/README.md) · [Nova Launcher](https://www.apkmirror.com/apk/teslacoil-software/nova-launcher/nova-launcher-7-0-58-release/nova-launcher-7-0-58-android-apk-download/) · [Lawnchair](https://github.com/LawnchairLauncher/lawnchair/releases/tag/1.2.0.1884) · [LauncherHijack](https://github.com/BaronKiko/LauncherHijack/releases/tag/403)

The bundled **Play services 24.35.30 APKM** has SHA-256 `f66cde17119f1915584700b2ad47c7209022d6ad436e41dd5888f7de04157974`. We downloaded the same version from the linked APKMirror listing and verified its published SHA-256, `14ec073ee4995d845a0ad893806e8372881a081dfff1e07665a33239eeb7547b`. Every APK supplied by Hayden, the base and 25 splits, matched the corresponding APK in that download byte for byte. APKMirror’s current bundle adds a 480 dpi split and updates the outer metadata and signature records. Those differences explain the changed archive hash. ## Malware scan and limits

The manual source review found no code that uploads tablet files or credentials. ClamAV 1.5.5 loaded 3,628,228 official signatures (main 63, daily 28194 dated November 25, 2026, and bytecode 339).

| Scanned input | Result | Elapsed |
| --- | --- | ---: |
| Pinned GitHub source ZIP | Zero detections, no warnings | 15 s |
| Published Python ZIP | Zero detections, three legacy Android check timeouts | 7 min 45 s |
| All 22 files extracted from the Python ZIP | Zero detections, the same check timed out on Play services, Play Store and Nova | 7 min 44 s |
| Published Linux archive | Zero detections, two legacy Android check timeouts | 10 min 30 s |
| All 371 Linux files absent from the Python ZIP | Zero detections, no warnings | 17 s |

The release scans raised no archive-limit alerts. One legacy Android check failed to finish on the affected inputs, so its coverage is incomplete. We did not launch the upstream application or its installers, install the APKs, or test on a physical tablet. The results apply to the listed downloads. They do not establish how the compiled software behaves or what a later update might install.
