Independent package workflow review, 2026-11-27

Verdict — changes required before release. Five Important findings.

Critical

None identified.

Important

1. A rejected first change erases the preceding batch's usable undo.
   package_workflows.py lines 494–499 replace the device's journal with the
   new package before the command. In the stateful Tablet fixture, disabling
   Kindle succeeded, then Android denied disabling Photos. Kindle remained
   disabled. The next undo preview contained only Photos, which was already
   enabled. Retain the preceding journal alongside the pending first change
   until the new batch has a confirmed effect. Preserve enough information
   to recover when a command's result is uncertain.

2. A failed two-step undo hides a confirmed change.
   package_workflows.py lines 461–474 restore an uninstalled package, check
   that it is installed, then apply its saved enabled/disabled state. Line
   499 records completion only after both operations finish. In the fixture,
   undoing removal of a previously disabled Kindle reinstalled it, then a
   denial of disable-user left it enabled. The error reported only the denial.
   Record the confirmed reinstall before the next command and retain the
   remaining disabled-state target for retry.

3. Stock launcher recovery requires a working current HOME.
   package_workflows.py lines 196–205 and 342–347 parse the current HOME as a
   component before looking up the stock HOME, even for launcher-restore.
   With stock disabled and global resolution returning "No activity found",
   the fixture rejected the preview with "Expected an Android component in
   package/.Class format." The stock-specific HOME still resolved. Represent
   a recognized no-current-HOME result in the restore preview, verify the
   stock-specific component, and permit its enable-and-select sequence.

4. Replacement installs can report success for the old installed version.
   package_workflows.py lines 450–456 check only that the package ID exists
   after adb install accepts the APK. In a focused system-update probe,
   the reviewed APK had version code 42 and install returned Success, while
   pm path still pointed to /system/app/com.amazon.kindle/base.apk. The
   workflow returned "Installed com.amazon.kindle for owner user 0." Verify
   the installed package's version and the installed APK's digest when
   readable, including replacements with the same version code. Report an
   accepted but unverified installation when readback is insufficient.

5. Empty OTA selections authorize every installed known updater.
   package_workflows.py lines 265–269 default an empty selection to UPDATERS.
   Calling plan_package_action(serial, 'ota-disable') in the fixture produced
   a plan selecting com.amazon.device.software.ota. feature_catalog.py lines
   70–71 expose neither OTA operation's package selector. The brief requires
   explicit package selection. Require a nonempty known selection, expose
   it through the UI, and retain the existing preview and undo.

Minor

None additional.
