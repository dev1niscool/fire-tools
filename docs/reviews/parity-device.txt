Coverage and boundaries
-----------------------
* Device readouts include scoped settings, processes, up to 500 log records,
  installed IMEs, users, home, package details and storage/battery statistics.
* Setting changes capture the original value locally and verify listed state.
  Imports bind to serial hash, model, SDK and the digest of the reviewed file.
  Exports cover allowlisted display/UI, sound and privacy values. Unsupported
  firmware values appear as omissions in the preview. An exact value readback
  establishes neither visible UI changes nor reduced telemetry.
* Optional package restoration handles differing enabled/disabled states for
  currently installed, non-protected catalog packages. The preview lists skipped
  unavailable or unrecognized packages. It cannot reinstall missing APKs or
  recover private app data. Combined backups contain configuration metadata.
* File transfers target canonical paths in owner shared storage. New local
  outputs publish from temporary staging. Files are limited to 512 MiB. A
  shared folder is limited to 4,096 entries, 4 GiB and a ten-minute enumeration
  or transfer window. Shared storage can change independently while copying.
  APK extraction uses each owner package-manager path. No OS image or private
  app-data backup is produced.
* ADB and the tablet must implement each command. File workflows require
  ordinary Android utilities including realpath/stat, and push requires
  no-clobber mv -nT. A refusal stops the operation. A device disconnect can
  leave a unique temporary capture or upload file on the tablet. Local atomic
  no-replacement directory publication requires Windows, Linux renameat2, or
  macOS renamex_np. No hardware or Windows/macOS validation was performed.
* Helpers are checked against the supplied source-build signer using local
  verification tools before WRITE_SECURE_SETTINGS is requested. The user
  then chooses the actual helper action on the tablet. Accessibility enables,
  wallpaper selection and lockscreen credentials likewise require tablet UI.
  Parental controls open tablet Settings; automatic visibility changes are
  unavailable. A helper launch does not establish ad removal.
* Remote input, display overrides, rotation, app-ops, permissions, user
  changes and power requests use ordinary, owner-scoped ADB. Reboot requests
  report acceptance, without claiming a completed boot. An expert shell
  accepts one reviewed token list. There is no credential bypass, automatic
  factory reset, firmware flashing or elevated execution.

Round-one review fixes
----------------------
All five findings from parity-device-review.txt were addressed.

1. Generic grants reject WRITE_SECURE_SETTINGS for org.firetools.adshelper.
   The shared permission executor independently requires the signer-verified
   helper-start or helper-restore plan and checks the installed APK again.
2. First-time and existing undo files, reviewed local input files and output
   staging/publication now use pinned directories. POSIX traverses with
   O_NOFOLLOW and openat-style dir_fd operations. Windows holds non-reparse
   directory handles throughout traversal and publication, denying write/delete
   sharing on each component. Linux uses parent-process descriptor paths for
   ADB output. macOS stages child-process transfers privately before copying
   into the held destination. A host without a usable directory descriptor
   path or handle refuses the affected operation.
3. Package, display, permission, app-op and profile writes record acceptance
   before another tablet request can fail. Remote upload publication and local
   file publication are recorded before cleanup. Readback upgrades the entry.
4. Advanced device reads check the selected Amazon owner tablet before
   collecting diagnostics or configuration.
5. Owner permission/app-op previews capture the exposed previous state, show
   it to the user and recheck before mutation. A preview explicitly identifies
   unexposed values. The helper grant also binds its prior permission state.

Round-two re-review fixes
-------------------------
The previous module and tests are preserved under /workspace/device-round2-base.
The isolated change set is /workspace/parity-device-round2-fix.diff.

Private staging no longer registers a pathname for recursive cleanup by
TemporaryDirectory. The original staging directory stays pinned while cleanup
handles its output/snapshot entries. Cleanup checks the staging entry identity
and leaves both directories untouched if a replacement is present. The last
pathname operation is a non-recursive rmdir. The regression replaces the
staging entry itself with a different populated ordinary directory, including
a nested file, and checks that both replacement files survive.

App-op snapshots retain UID and package modes separately, show the exposed
scopes in the preview, and bind both before requesting the change. An explicit
UID mode that disagrees with the requested mode now reports its observed
value on readback, including when the package line agrees. The accepted
command remains visible in partial progress.
