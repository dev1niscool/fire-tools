Optional Android ads helper review

Implemented the independent Java app, local Android SDK builder, setup and removal instructions, and six focused host tests. The only exported component is org.firetools.adshelper/.MainActivity. Turning on enforcement, stopping it, and restoring require on-device interaction. The foreground notification has a Stop action. BOOT_COMPLETED can resume enforcement after normal boot only while the saved preference is enabled, the ADB grant is present, and notification visibility checks pass. The app enforces one Global setting on its foreground timer and after screen wake. Its persisted backup distinguishes an absent entry from a present null or text value. Restore reads back the original value and presence before clearing its backup.

The initial build compiles against API 36 and targets Android 9 (API 28) for its foreground service and notification compatibility behavior. The current minimum API is recorded in the follow-up below. The manifest grants WRITE_SECURE_SETTINGS, FOREGROUND_SERVICE, RECEIVE_BOOT_COMPLETED, and POST_NOTIFICATIONS. The fourth permission covers Android 13+ notification consent. The manifest declares no network permission and disables Android backup. The SDK check confirmed the service and boot receiver are private and the app launcher is exported.

Follow-up for API 23 notification blocking

- The app now requires Android API 24 (Android 7.0), where NotificationManager.areNotificationsEnabled is public. Android API 23 has no public preflight for the user notification switch. Its AppOps POST_NOTIFICATION operation has no public string mapping. The desktop toolkit still supports API 23 tablets.
- The helper requires a positive app-level notification check before startup and each enforcement pass. On API 26 and newer it also requires an available, unblocked notification channel. A missing notification manager stops enforcement.
- The new regression failed with the old minimum of 23 and passed after the manifest and D8 minimum were updated to 24. All seven companion host tests passed with OpenJDK 21. A concurrent run of all 172 tests showed four failures and six errors in test_device_workflows and test_extra_workflows as those implementations were being revised. No companion test failed.
- The app rebuilt with official Android Platform 36 and Build Tools 36.0.0. aapt2 reported minimum 24 and target 28. The rebuilt APK verified with v2 and v3 signatures, passed alignment and ZIP checks, and had SHA-256 748557ca7c4120d83c100dc1543ae791d7d387a7b2c4418fefabdab127b9a563. ADB still showed no devices attached.
