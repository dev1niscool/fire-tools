Package workflow implementation and verification
2026-11-27

Scope
Owner package administration uses ordinary serial-scoped Android commands through
the existing Toolkit confirmation and operation lock. Every device mutation
rechecks the Amazon model, identity and foreground owner profile.

Inventory covers installed, system, third-party, disabled and removed-for-owner
packages. Selected apps can be disabled, enabled, uninstalled with retained data,
restored from an existing image, cleared, stopped and launched. Core platform,
provider, settings, installer, shell and input infrastructure has protection.
The 20-app standard preset and 29-app complete preset are original selections
of optional package IDs observed in the static Toolbox inventory. The complete
profile adds services including Appstore, metrics and messaging. Custom UTF-8
lists accept comments and up to 256 unique IDs. Preview shows affected and
skipped apps. Dedicated Special Offers and OTA operations report package state.

The last state-changing batch is journaled before each attempted mutation, in a
bounded atomic JSON file keyed by serial hash and model. Undo checks the preview
against the current owner states and saved targets. If Android discarded an APK
entirely, undo can restore the other apps and retain the missing app's record.
Earlier successful actions are included in partial-failure diagnostics.

Launcher selection validates HOME resolution before permitting stock disable.
Stock restoration resolves an installed Fire HOME, enables it and checks the
post-switch result. Keyboard selection looks up all installed IMEs, enables the
requested service and checks the secure default. APK installation previews file
and signer fingerprints, verifies SDK/ABI/signatures with configured official
tools, stages and verifies the complete batch before the first owner install,
and enforces the Google pin for Play identities. System updates additionally
require exact selected installed system package and matching APK identity.
Factory rollback requires package-specific command support and verifies a move
from the updated data APK path to a factory APK location.

Limitations
No physical Fire tablet was available. Fire OS may deny commands, ignore a
default launcher, resurface lock-screen ads or continue updating by another route.
Inventory labels for unrecognized IDs are the IDs themselves. Package undo
restores the installed/disabled state; data clearing and factory rollback can
lose data permanently. Android may require the original signed third-party APK.
The install workflow accepts standalone local APKs. Split bundles, downloader
catalogs, version downgrades, widget grants and alternate HOME interception
methods remain outside this package implementation. Factory rollback is permitted
only on firmware advertising a package-specific form; it can affect all profiles.

Independent review round 1
The five findings in parity-packages-review.txt were reproduced with the public
Toolkit API and a synthetic Android command boundary. A pending first change is
now journaled alongside the preceding batch. Readback after an ordinary failure
retains the applicable batch. Interruption before or after the write can be
resolved using the tablet state at the next preview. A confirmed install-existing
substep of a multi-step undo is reported even if restoring disablement fails.

Stock HOME recovery now recognizes Android's exact no-activity response, still
requires a stock-specific HOME, and checks it again after enabling stock.
Permission failures and malformed responses stop recovery. OTA enable/disable
requires at least one explicitly selected, known updater. Generic and system APK
installs now record Android's acceptance before readback, verify owner registration,
pull the standalone installed APK into private staging with size and device checks,
and compare its digest against the reviewed signed APK. Exact content equality
establishes its version code, package identity and signing certificates. Firmware
that denies this readback leaves the install accepted but unverified, and stops
the remaining batch.

Package journal directory hardening
Package journal reads and atomic writes now use the shared pinned-directory
helper. Reads reject a symlink or reparse point in the journal path, including
the journal file itself. Saves retain the same directory handle during staging,
atomic publication and cleanup. A rename of the original parent during a save
therefore cannot redirect the journal to a replacement directory.
