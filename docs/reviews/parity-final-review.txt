Verdict — changes required before publication. Four high-severity findings,
two medium-severity findings and one low-severity finding.

High

1. CLI confirmation can install a different APK and signer from the preview.
   open_fire_toolkit/cli.py lines 102–115 and package_workflows.py lines
   412–431. The documented two-invocation procedure regenerates the plan
   on the --yes invocation and executes immediately. With the real CLI and
   Toolkit, the synthetic APK verifier and a simulated tablet, I previewed
   a file signed by A, changed that input to a file signed by B and repeated
   the same command with --yes. It exited 0 and installed B. The staged-file
   verification correctly matched B to the second, automatically accepted
   plan. The same two-invocation design permits the target set of a custom
   debloat operation to change. Bind execution to a digest of the reviewed
   plan, or allow confirmation of the same in-memory preview. Retain a way
   to confirm a reviewed batch of APKs with different signers.

2. The operation lock and undo records can refer to different directories.
   open_fire_toolkit/service.py lines 225, 140 and 160. The lock is held in
   the initial directory. Each undo reader/writer opens the canonical path
   again. Device and package journals also open it independently. In a POSIX
   temporary directory, I paused a confirmed ads action after lock creation,
   renamed the state directory and recreated its original name as an ordinary
   directory. A second Toolkit accepted a reboot plan while the first lock
   still existed. The first then changed the ads setting and put state.json
   in the replacement directory. Both actions reported success. Bind journal
   access to the directory held for execution and check that the configured
   location still names it before writes. A directory replacement should
   invalidate the active operation and preserve its recovery records.

3. Package workflows omit accepted writes and can confirm the wrong device.
   open_fire_toolkit/package_workflows.py lines 485–505, 535–546, 557–582,
   612–616 and 628–632. With the existing Tablet.change_after fixture, a
   one-package disable returned a confirmed disabled state even though the
   model changed from Fire to Other immediately after the command. With two
   packages, a disconnect on the first inventory read after disabling Photos
   produced a partial report listing only Kindle. The fixture showed both
   apps disabled. The system-update rollback and component paths also perform
   diagnostic reads before recording accepted commands. Record each accepted
   mutation and target immediately, then verify tablet identity and owner
   before trusting readback. Upgrade the progress entry after verification.

4. The recommended helper setup can grant the elevated settings permission
   to a previously installed APK. companion/README.md lines 21–26 present
   three independent shell commands. If installation fails, a paste into
   the documented shell continues with the unverified package-name grant.
   This occurs, for example, when a previous installation remains under a
   different signing key. The desktop already verifies the installed bytes
   and user-supplied signer before granting WRITE_SECURE_SETTINGS. Route the
   setup instructions through helper-start and the signer printed by the
   local build, including first-install and existing-install cases.

Medium

5. Restoring a package snapshot bypasses package undo. In
   open_fire_toolkit/device_workflows.py lines 748–758 and 1018–1032 the
   standalone and combined restore paths apply package-state steps directly.
   The pre-restore state exists in the preview but never enters a journal.
   An isolated package export followed by changing Kindle's state and
   restoring the file changed the app back and created no undo directory.
   The input snapshot contains the target state, so it cannot recover the
   pre-restore state. Route these steps through the existing package journal
   semantics, retaining the pre-restore states after partial completion.

6. Source archive generation includes private local files by extension.
   scripts/package_release.py lines 12–30 select all .png/.txt files below
   docs and most .xml/.md files below companion. A temporary source tree
   containing docs/images/my-tablet.png, docs/local-logcat.txt and
   companion/local-notes.xml selected all three for publication. A screenshot
   saved to the first path through the new tool would be included in the ZIP.
   The actual reviewed checkout had no such files or untracked selected
   entries. Use a distribution inventory that identifies intended repository
   files, works in the extracted source tree, and excludes local additions.
   Exercise inclusion of the demo screenshot and exclusion of private images
   and text records in the release tests.

Low

7. The parental-control form offers two options with identical behavior.
   open_fire_toolkit/feature_catalog.py line 94 and device_workflows.py
   lines 768–776. Through the public catalog, both show and hide previewed
   exactly one action, opening android.settings.SETTINGS. The preview warning
   and feature matrix explain the firmware limitation. Label the form as a
   Settings shortcut and remove the ineffective visibility choice from the
   public catalog. Existing command-line aliases can retain their explicit
   limitation message if compatibility is desired.
