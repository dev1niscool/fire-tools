# Fire Tools parity expansion plan

Spec: `docs/superpowers/specs/2026-11-27-parity-design.md`.
Base: 95fe9e4. Existing isolated task checkout, branch feat/feature-parity.
Execution: parallel agents with disjoint file ownership; root integrates and commits. User delegates decisions and explicitly authorizes GitHub upload. No approval waits.

## Global constraints

Python 3.11+ standard library. Official tools supplied by the user. No original code/assets/binaries. No target execution. Explicit serial, Amazon owner profile, preview and confirmation, current-device recheck, bounded subprocesses, no shell=True. Do not claim hardware or firmware validation. Demo performs no subprocess/network/file actions. Unknown/failed outcomes must not be reported as successful.

## Shared interfaces

New frozen `WorkflowPlan` in workflows.py has title:str, serial:str, details:tuple[str,...], warnings:tuple[str,...], action:str, device:DeviceInfo, operation:str, parameters:tuple[tuple[str,str],...]=(), packages:tuple[str,...]=(), snapshot:tuple[tuple[str,str],...]=(), apks:tuple[ApkInfo,...]=(). `.params` returns dict(parameters). Actions are package_workflow/device_workflow. Existing service Plan remains unchanged.

`PackageWorkflows` mixin public API: `package_inventory(serial, mode='all')->list[dict[str,str]]`, `plan_package_action(serial, operation, packages=(), **parameters)->WorkflowPlan`. Execute hook `_execute_package_workflow(plan, completed:list[str], log)->None`.

`DeviceWorkflows` mixin public API: `read_device_tool(serial, operation, **parameters)->str`, `plan_device_action(serial, operation, **parameters)->WorkflowPlan`. Execute hook `_execute_device_workflow(plan, completed, log)->None`.

Both mixins may use existing Toolkit methods `_writable_device`, `_verifier`, `_state_key`, `state_dir`, `adb.shell`, `adb._run_device`, and lazy imports of service.ToolkitError. Do not modify service.py or adb.py; root wires Toolkit inheritance and dispatch. Per-step recheck is required. New workflow-specific undo uses separate bounded JSON files, with atomic writes and binding to tablet model/serial hash. Export/read actions with host writes use plan/confirmation too.

Fetch/reconcile existing dev1niscool/fire-tools main and publish fast-forward, preserving visibility. Verify remote files/head.

## Review focus

- Batch failure after a successful removal: report partial completion and retain usable undo.
- Device/profile/package state changes after preview: refuse stale action before next write.
- Malformed exported/imported JSON and package/path/component injection: reject without executing or writing.
- Host output paths and symlinks: never silently overwrite or read special files; bound external outputs.
- Claimed success despite Fire OS refusing settings/package operations: read back wherever possible and distinguish command accepted from visible feature behavior.
