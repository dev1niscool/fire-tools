# Fire Toolbox 46 feature audit

Research date: 2026-11-27. Comparison baseline: Open Fire Toolkit commit `95fe9e4` (0.1.0). This document records the starting gaps, not the implementation status of later commits. **The baseline is not feature-complete with Fire Toolbox 46.** The target is the Windows 46.0 assembly; Linux releases can have a different interface and feature set.

## Evidence and confidence

The original `Fire Toolbox V46.0.exe` has SHA-256 `34be37dff0c3bf40cb34155896e92b70d9dfdff5cb969c780cade88f13f74079`. Its metadata reports assembly version 46.0.0.0. It was not executed. The audit reads the already decoded managed metadata, CIL summaries and strings in the separate investigation workspace, plus the REA evidence described in [REA-NOTES.md](REA-NOTES.md). No original binaries, assets, decompiled code or APKs should be distributed in this repository.

Relevant local evidence is `/workspace/fire-toolbox-review/static/il_summary.json`, `all.il` and the REA `artifact.json`, `members.json` and `utils.json`. Method/class anchors below identify reproducible evidence without embedding the original implementation. UI strings and matching action methods establish that a workflow exists in the inspected assembly; old handlers can remain in the assembly and are not proof every option is reachable on every tablet. Hardware success and complete click-by-click behavioral equivalence have not been tested.

## Practical implementation primitives

These command families are behavior references, not unconditional compatibility promises. Every command should be sent through the selected-device boundary, with user/profile context explicit where supported, bounded output/time, validated values and factual postcondition checks. [Android's ADB documentation](https://developer.android.com/tools/adb) documents installation, package and activity managers, file copy and capture. Its existence does not certify Amazon-specific permission availability.

| Workflow | Primitive / command family | Required details |
| --- | --- | --- |
| App inventory | `pm list packages --user 0` with `-s`, `-3`, `-d`, `-e`, `-u`; `dumpsys package PACKAGE` | Distinguish installed-for-user, disabled and present in system image. |
| Disable / restore | `pm disable-user --user 0 PACKAGE`; `pm enable --user 0 PACKAGE`; `cmd package install-existing --user 0 PACKAGE` | `enable` cannot reinstall an app removed for that user; restore must inspect original state. |
| Remove for user | `pm uninstall --user 0 PACKAGE`, optionally `-k` to retain data | This does not erase an immutable system image. Warn when data is removed. Third-party app restoration may need original APK. |
| Clear / stop / launch | `pm clear --user 0 PACKAGE`; `am force-stop --user 0 PACKAGE`; `am start --user 0 -n COMPONENT` | Clearing data is not reversible; resolve/validate the activity. |
| Export apps | `pm path --user 0 PACKAGE`; `adb pull` each returned path | Preserve complete split sets and a manifest of package/version/signer. |
| Sideload | `adb install -r --user 0 APK`; `adb install-multiple -r --user 0 BASE SPLITS...` | Verify all inputs before first write. Downgrade and permission grants are separate opt-ins; no automatic skip of signatures. |
| Launcher | `pm set-home-activity --user 0 COMPONENT`; `appwidget grantbind --package PACKAGE --user 0` | Snapshot existing home; verify replacement resolves before considering stock-launcher disable. |
| Keyboard | `ime list -s`; `ime enable COMPONENT`; `ime set COMPONENT` | Android version/user flags vary. Keep prior method enabled until new one is active. |
| Privacy/settings | `settings --user 0 get/list/put/delete NAMESPACE KEY [VALUE]` | Namespace allowlist; preserve missing-versus-present. Relevant privacy keys: secure `USAGE_METRICS_UPLOAD_ENABLED`, `usage_metrics_marketing_enabled`, `limit_ad_tracking`, `advertising_id`; global `HOUSEHOLD_ID`. |
| Ads | global `LOCKSCREEN_AD_ENABLED`; package `com.amazon.kindle.kso` | Separate setting, package mode and persistence. Don't clear data merely to make a reversible action appear to work. |
| Display | `wm density`; `wm size`; `wm overscan`; `cmd uimode night`; `cmd overlay`; settings values | Probe feature availability. Overscan and overlays can be unavailable or affect input visibility. |
| Shared files | `adb push`, `adb pull`; tokenized `ls`, `mkdir`, `mv`, `rm` | Constrain device paths, reject traversal, distinguish copy overwrite and destructive delete, no wildcard evaluation. |
| Capture | `adb exec-out screencap -p`; `screenrecord REMOTE.mp4` followed by pull | Output binary to a private temporary file; publish final output only on verified completion. |
| Logs/tasks | `logcat -d` or bounded streaming; `ps`; `dumpsys meminfo`; `/proc/meminfo` | User-controlled log export; never publish logs or device identifiers with repository source. |
| Networking | ADB `connect`/`disconnect`/`pair`/`tcpip`/`usb`; selected `cmd netpolicy` and `settings` operations | Validate endpoint; confirm before changing transport; a standard ADB port is not encrypted pairing. |
| Power | `adb reboot`, `reboot recovery`, `reboot bootloader`; shell `reboot -p` | Distinguish request accepted from completed reboot or shutdown. |
| User administration | `pm list users`; `pm create-user`; `am switch-user`; `pm remove-user` | Exclude owner deletion; warn about Fire parental-control cleanup. Creation and deletion are not routine reversible toggles. |

## Firmware limits and parity criteria

1. A newly purchased device is not proof of its exact generation or OS build. Record model, `ro.build.mktg.fireos`, Android API and security patch before feature decisions. Amazon documents that [Fire OS 8 incorporates Android 10/11 changes](https://developer.amazon.com/docs/fire-tablets/fire-os-8), including newer signature requirements and background restrictions. This provides an Android baseline, not a guarantee that ordinary Android shell operations are permitted.
2. In the original itself, `MainMenu.CheckOSVer` has a protected-update-package warning; `RemoveAds.ToggleAds` contains a temporary fallback; launcher mode descriptions distinguish persistence; exploit-mode messages describe app instability. Therefore even closed-source Toolbox does not promise all features work unchanged after every firmware update.
3. The original uses normal shell, a legacy debug-app route, an elevated mode, and companion apps in different branches. Reimplementing ordinary ADB requests cannot honestly be called the same as implementing every one of these branches.
4. Feature parity must separately track **implemented workflow**, **interface/options**, **dependencies/download convenience**, **undo behavior**, and **tested device/firmware result**. A row that opens Settings or supplies a generic shell should be labeled as such; it is not evidence that the original automated workflow is reproduced.
5. No release should claim full parity merely because every category has a menu entry. Unsupported operations should report the restriction and preserve prior state. Companion applications need independent provenance/signature checks; the original bundled assets must not become an implicit trust source.
6. Current baseline differences deliberately include no arbitrary APKs, no automatic downloads, no general shell, no exploits, no OTA blocking and no credential handling. Expanding scope requires replacing those earlier non-goals in the design, documentation and security model before presenting the result as complete.

## Recommended implementation order

First extend the user's three priorities: full reviewable Amazon package management (presets, custom lists, remove-for-user, restore), package-based ad controls with truthful firmware errors, and verified Google components plus management. Next add independent ordinary-ADB utilities: shared files, app export/sideload, backup manifests, settings/privacy/display, screenshots/logs, launcher/keyboard selection, and power options. Finally address workflows that need companion applications, curated downloads, alternate profiles or elevated access. Keep a release status matrix updated against tests and documented exclusions; the research matrix above remains the baseline inventory.
