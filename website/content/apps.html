Disable or enable one Amazon app

  1. Connect the tablet in the primary adult profile. Open Apps → Read app states to see which common Amazon apps are installed, including Audible and Kindle books.
  2. Select an app and choose Review disable. Check its package ID and tablet serial, then choose Confirm and run. A disabled app stays installed and keeps its data.
  3. Choose Read app states again. To restore the app, select its disabled row, choose Review enable and confirm.

Review a debloat preset

Open Apps → Compare debloat presets to see every app name and package ID before connecting your tablet. From the source folder, you can also run python -m open_fire_toolkit tool debloat-presets.

If you rely on Silk, the Appstore, Camera or Email, Standard leaves them available. If you need Kindle books or Prime Video, choose individual apps under Tools → Disable selected apps. Compare the v46 package IDs.

  1. Open Apps → Debloat Amazon apps. Choose Standard, Complete or Load From File... for the primary adult profile. A custom list can be a Toolbox .debloat file or a plain package list.
  2. Choose the action. Automatic (follow list type) disables built-in presets and follows debloat or restore directives in custom files. Remove for owner (keep data) requests owner-only removal.
  3. Choose Review. Inspect the owner’s before/after states and skipped items. The preview filters out absent apps and protected packages.
  4. Choose Confirm and run. In Apps → Package inventory, select disabled and choose Read to verify.

Load an annotated Debloat.txt

Save a local copy of the list. Keep one package ID per line, for example com.amazon.kindle # Kindle books. In a plain text file, spaces or tabs can separate the ID from its comment. Put # at the start of a row to leave that app alone. In a Toolbox .debloat file or a list with a ListType= directive, a row containing # is skipped in full. View the reference Debloat.txt.

Choose Load From File..., select your copy and review the automatic action. Fire Tools matches exact IDs against the tablet’s owner inventory. The preview identifies protected services such as app verification, VoiceView and Device Setup. Confirming disables the listed eligible apps and keeps their data. To reverse this batch, choose Undo saved package changes.

Restore your apps

  • To reverse your last batch, choose Apps → Undo saved package changes → Review on the same computer and tablet. This restores saved states after an interrupted batch. If an older record would disable or remove a newly protected service, Fire Tools skips that change and keeps its record. Review and confirm before a new batch replaces the record.
  • To enable eligible apps across the Complete preset, choose Apps → Restore Everything → Review. Check the disabled apps it proposes to enable, including any you disabled separately. This works without a saved batch.
  • Choose Tools → Restore apps removed for owner and review the package. Built-in apps retain their system image. If a third-party package has disappeared from storage, restoring it may require the original signed APK.
  • Keep packages-state.json for batch undo. Fire Tools saves the file in the desktop user’s state directory. Undo restores package states. Clearing app data is irreversible. Find the state directory.

Install a folder of standalone APKs

Put only the APKs you want to install in an otherwise empty folder. Select your tablet in Connection, then open Tools → Install a folder of APKs. Choose the folder and review every filename, package ID and signer. A valid signature identifies the key used to sign the file. Compare its fingerprint with the publisher’s record, or enter a trusted fingerprint to require a match for every APK. Confirm after checking the list. Android handles runtime permission requests when you use each app.

For Google Play, use the Google Play guide and its dedicated installer, which checks Google’s signer and component order.
